An agent that clicks like a person and inspects like a test.

Write goals and expectations. An LLM agent drives a real browser through agent-browser and checks what's on screen, and the console, uncaught errors, network and app state.

// specs/todos.qa.ts — parsed, never executed
suite('todos journey', { as: 'qa' }, () => {
  step('go to the list', () => {
    goal('open the Todos page from the nav');
    expect('it lists at least one todo');
  });
  step('add a todo', () => {
    goal('add a todo "${params.todo}"');
    expect('the list contains "${params.todo}"');
    expect.network('POST /api/todos').status(201);
    expect.console.noErrors();
  });
});

Why qaspec

Classic E2E tests are slow to write and blind to what they don't assert. Agentic frameworks hide the console and network from the model. qaspec gives the agent both.

Intent, not locators

Specs are goals and expectations. No selectors, waits or helpers. Anything outside the DSL is rejected with file:line:col.

Sees what a test sees

Console errors, uncaught exceptions, every request and status, localStorage, any JS expression, checked per step.

Many checks, one file

A suite is an ordered journey. Steps share browser state. A failure skips only the steps that depend on it.

One browser per run

A Chromium session costs about 1.5 GB of memory. qaspec uses a single agent-browser session with one tab per project, and --keep-open reuses it across runs.

Sign in once

Identities sign in with a login spec or by themselves. The state is saved with mode 600 and reused until valid_if fails.

Secrets stay secret

The model only sees secret names. Values go through agent-browser's stdin, never argv, and are redacted from every log and report.

Install

A single Rust binary. The only runtime dependency is agent-browser.

npm i -g agent-browser && agent-browser install
cargo install --git https://github.com/jaivial/qaspec --tag v0.1.0

qaspec init      # qaspec.toml + specs/home.qa.ts
qaspec check     # validate specs, config, secrets — no browser
qaspec run       # everything, in one browser session

Projects, environments, credentials

Everything a spec needs to know lives in qaspec.toml. Specs only name things.

default_env = "local"

[projects.app]
specs  = "specs/app/**/*.qa.ts"
health = "/health"
[projects.app.env.local]
base_url = "http://localhost:3000"
[projects.app.env.dev]
base_url = "https://dev.example.com"

[projects.app.identities.qa]
username = "qa@example.com"
password = { env = "APP_PW" }
valid_if = { url_not = "/login" }

[projects.admin]
depends_on = ["app"]
[projects.admin.env.local]
base_url = "http://localhost:4000"

[llm]  # any OpenAI-compatible endpoint
base_url = "https://api.openai.com/v1"
api_key  = { env = "OPENAI_API_KEY" }
actor    = "gpt-4.1-mini"
